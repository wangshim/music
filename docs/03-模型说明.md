# 03 - 模型说明

## ASR 模型

| 项 | 值 |
|---|---|
| 模型名称 | sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17（SenseVoice-Small，非流式） |
| 支持语言 | 中文 / 英文 / 日文 / 韩文 / 粤语（App 内固定 `language='zh'`） |
| 用途 | 离线语音转写（ASR），全程本地推理，不上传音频 |
| 推理框架 | sherpa-onnx（Dart 绑定 `sherpa_onnx ^1.13.6`，`OfflineRecognizer`） |
| 特点 | 非流式整段建模，自带标点与逆文本规整（ITN），断句更自然、数字与专名更规整 |

## 模型文件与打包位置

模型文件位于项目 `assets/models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17/`：

| 文件 | 大小 | 说明 |
|---|---|---|
| `model.int8.onnx` | ~228 MB | SenseVoice-Small 量化模型（单文件） |
| `tokens.txt` | ~0.3 MB | 词表 |

`pubspec.yaml` 的 `assets:` 段只声明上述 2 个文件。`flutter build` 时打包进 APK 的 `assets/flutter_assets/assets/models/...`，对应 APK 增加约 133 MB（模型本身压缩后约 153 MB）。

## 打包与加载机制

1. `pubspec.yaml` 显式声明 2 个模型文件（不声明目录，避免子目录文件漏打包）。
2. 转写时 `lib/services/asr_service.dart` 用 `rootBundle.load()` 把模型从 APK 解压到应用缓存目录（`Directory.systemTemp/audio_analyzer_models_sensevoice`），再传给 `sherpa_onnx.OfflineRecognizer`。
   - 原因：Android 上 Flutter assets 位于 APK 内部，不是真实文件路径，C++ 层无法直接读取，必须先解压。
   - 按 8 MB 分块落盘，并先写 `.tmp` 再原子重命名，避免中途被杀进程留下半截文件。
   - 已存在且非空则复用，避免每次启动重复解压。

## 推理参数

| 参数 | 值 | 说明 |
|---|---|---|
| `language` | `zh` | 固定中文 |
| `useInverseTextNormalization` | `true` | 输出标点、阿拉伯数字（ITN） |
| `provider` | `cpu` | 纯 CPU 推理 |
| `numThreads` | 2~4（按 CPU 核数） | 兼顾速度与功耗 |
| `decodingMethod` | `greedy_search` | 贪心解码 |
| 采样率 / 特征维度 | 16000 / 80 | 需 16k 单声道 WAV 输入 |

长音频按 25 秒、优先在低能量静音点切段，逐段识别后拼接（上段已含句末标点则直接相接，否则补中文逗号）。

## 仓库策略：模型不入库

`model.int8.onnx` 为 228 MB，超过 GitHub 单文件 100 MB 硬限制，因此：

- `.gitignore` 已排除整个 `/assets/models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17/` 目录，模型不进入 Git 历史。
- 克隆仓库后需按下方「下载方式」补齐模型文件，否则 `flutter build` 会因 assets 缺失而失败。
- 如需克隆即用，可改用 Git LFS 跟踪该文件（本机已安装 git-lfs 3.3.0，注意 LFS 免费存储配额），或在 CI 中预下载。
